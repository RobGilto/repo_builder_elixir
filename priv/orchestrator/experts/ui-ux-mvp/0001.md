# UI/UX MVP — orchestrator mental model

## When a UI/UX phase is warranted
- After backend phases pass, run surface detection on the app.
- If a front-end surface exists (web / desktop / tui), append one `:ui_ux` phase per surface via `plan_phases`, each with `kind: "ui_ux"` and its `surface`.
- No surface detected => skip UI/UX entirely. Do not invent a surface.

## Per-surface scoping
- web => Playwright screenshot + accessibility snapshot + console/network rubric.
- tui => terminal snapshot + layout/keybinding assertions.
- desktop => window screenshot where launchable; otherwise an honest block/fail with a clear reason (never a faked pass).

## The four stages, UI-flavored
- spec => a UX design brief for the surface.
- implement => build/refine the interface.
- test => visual/behavioral validation with real evidence (artifacts), not a self-report.
- review => apply the ui-ux-foundations rubric. A failed review re-enters the fix loop.

## Iteration cap & MVP exit criteria
- The review->fix loop is the iteration engine, bounded by `:ui_iteration_cap` (default 3).
- Exit when the rubric passes OR the cap is hit, whichever comes first.
- Then the phase auto-completes, marked "MVP reached / capped".
- Stop at a decent MVP. Do NOT gold-plate.

## Stop-at-MVP discipline
- Converge; do not polish forever.
- Each iteration fixes concrete rubric failures with evidence, then re-reviews.
